# 01 · Context

## What is SubSpace?

SubSpace is a platform that helps users save money through:

- Shared subscriptions
- Gift cards
- Credit card benefits
- Rentals
- Bill payments
- Wallet
- Member chat

The problem was not the number of features.

The problem was **how easily users could discover and understand them.**

## The Problem

<Callout type="warn" title="Many ways to save, but poor discovery">

Subscriptions were easy to find and understand.

Other services such as **CardMatch, Rentals, Bills, and Gift Cards** were less visible.

Some flows also required too many screens before users could complete an action.
</Callout>

### I focused on three problems

1. **Discovery** — How can users notice all the ways SubSpace can save them money?
2. **Relevance** — How can we show users services that are useful to them?
3. **Efficiency** — How can we reduce unnecessary steps?

# 03 · Design Direction

The redesign followed three simple ideas:

### Discover → Understand → Act

**Discover**  
Make different ways to save easy to find.

**Understand**  
Explain why a service is useful to the user.

**Act**  
Make the next action simple and quick.

## Information Hierarchy

I gave Home and Explore different jobs.

### Home — Quick access

Home focuses on:

- Search
- Popular subscriptions
- More ways to save
- Personalized recommendations
- Popular content

### Explore — Discover

Explore focuses on:

- Subscriptions
- Credit Cards
- Gift Cards
- Rentals
- Bills
- Subscription activity

This removes the overlap between the two screens.

## Wireframing

I explored different layouts before moving to high-fidelity designs.

The main questions were:

- What should users see first?
- How can other services become easier to discover?
- Where should recommendations appear?
- How can Home and Explore have different purposes?
- Which steps can be removed from the Rental flow?

# 05 · Personalized Cross-Vertical Engagement

## The Problem

A user may come to SubSpace only for subscriptions and never explore the other services.

A generic promotion like:

> **"Buy a Gift Card"**

can feel like an advertisement.

## The Idea

**Show based on interest.**

Use what the user already does to suggest the next useful service.

For example, if a user already spends:

**YouTube Premium — ₹375/month**  
**JioHotstar — ₹149/month**

SubSpace can show:

> **You've spent ₹524 on subscriptions this month.**  
> Buy a discounted Gift Card before your next renewal and save more.

The recommendation is based on something the user already pays for.

### The flow

**Existing activity → Relevant recommendation → Clear saving → Action**

## Why this is different

The goal is not to push another product.

The goal is to answer:

> **"How can I save money on something I already use?"**

This creates a stronger connection between SubSpace's different verticals.

It also supports the marketplace flywheel:

**More relevant discovery → More users use other verticals → More activity across the marketplace → More value for users**

# 06 · Reducing Steps

## Rental Flow

The Rental journey had an unnecessary browsing step.

### Before

**Home → Rentals → Category → Product List → Product Details → Checkout**

### After

**Home → Rentals → Category/Product → Product Details → Checkout**

<ImageZoom
  src="/caseStudyimages/Subspace/ReduceSteps.png"
  alt="SubSpace rental flow before and after"
  width={1400}
  height={788}
/>

### Result

**5 steps → 4 steps**

Instead of sending users to another screen to browse products, products are shown closer to the category selection.

The goal was simple:

> **Show the product sooner and get the user closer to checkout.**

# 10 · Future Opportunities

The audit also showed a few opportunities beyond the redesigned screens.

## Onboarding

Introduce SubSpace before users enter the main app.

Explain:

- What SubSpace does
- How shared subscriptions work
- How users can save
- What the other services offer

## Product Tours

Use short guides when introducing a new feature or service.

This helps users discover features without permanently adding more UI to the screen.

## Personalization

Ask for the user's name during onboarding and use it for a simple greeting.

More importantly, use user activity to show relevant saving opportunities.

---

# 11 · Key Learning

The biggest learning from this project was:

> **More features do not automatically create more value.**

SubSpace already had many ways to save money.

The bigger problem was helping users understand:

> **"Which one can help me right now?"**

So I focused on connecting the user's current activity with the next useful action.

### The final approach

**Understand the user → Show a relevant way to save → Make the action easy.**
